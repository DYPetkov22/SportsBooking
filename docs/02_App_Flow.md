# 2. App Flow — потребителски потоци

## Гост
`Начало → Игрища / Спортове / Центрове → Регистрация или Вход`

## Регистрация
`Регистрация → Валидация на форма → Проверка за зает имейл → Създаване на Users профил → Създаване на Identity акаунт → Присвояване User → Автоматичен вход → Начало`

Важно: първоначалните Users seed записи са само бизнес профили; не са Identity акаунти и нямат пароли.

## Обикновен потребител
`Вход → Резервации → Нова резервация → Избор на игрище, дата и час → Валидиране → Проверка за припокриване → Запис → Моите резервации`

При грешни дати, начален/краен час или зает слот — съобщение до формата и отказ на записа. `Cancel` е POST действие за собствена активна резервация.

## Manager
`Вход → Игрища/Спортове/Центрове → Добавяне, редакция, изтриване` и `Резервации → Преглед/редакция/отмяна`, както и `Плащания → CRUD`.

## Admin
`Вход → Роли → Избор на друг акаунт → Назначаване User/Manager/Admin`; също администриране на бизнес профили в `Users`. Самопромяна на роля през интерфейса е забранена.

## Обработка на грешки
- Неавтентикиран потребител: пренасочване към вход.
- Липса на права: Access Denied/403.
- Несъществуващ обект: 404.
- Невалидни данни: форма с validation summary.
- Липса на SQL Server/LocalDB: приложението не стартира; виж `docs/SETUP_RIDER_BG.md`.
