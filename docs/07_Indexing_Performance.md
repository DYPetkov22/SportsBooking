# 7. Индексация и производителност

## Налични индекси и механизми
SQL Server автоматично създава индекси за `PRIMARY KEY`, `UNIQUE` email/sport и уникалния `Payments.BookingID`. В `database/02_Optional_Booking_Index.sql` е предоставен допълнителен индекс за проверки на резервации:

```sql
CREATE INDEX IX_Bookings_Field_Date_Status_Time
ON Bookings (FieldID, BookingDate, Status, StartTime, EndTime);
```

## Защо помага
Често изпълняваната заявка за зает слот филтрира по FieldID, дата, статус и сравнява началните/крайните часове. Композитният индекс може да ограничи прочетените редове при повече резервации. Не е задължително да се изпълнява върху малката demo база.

## Други оптимизации
- EF Core `AsNoTracking()` за четящи изгледи.
- `Include` само за нужните свързани данни.
- Уникални индекси за бизнес стойности, съобразени с правилата.
- При реален обем: paging, филтри по дата, анализ на SQL execution plans, наблюдение на бавни заявки.

## Ограничения и мониторинг
Сериалиционна транзакция се използва при create/edit на резервации, но тестове под конкурентно натоварване са необходими преди продукция. Не се твърдят конкретни числа за latency или throughput без измервания.
