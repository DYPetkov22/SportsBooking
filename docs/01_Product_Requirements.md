# 1. Product Requirements — SportsBooking

## Цел и обхват
SportsBooking е учебна уеб информационна система за резервация на спортни игрища, реализирана с ASP.NET Core MVC **.NET 9**, EF Core 9, SQL Server и ASP.NET Core Identity. Първоначалният ER модел съдържа шест бизнес таблици. Достъпът до управление на данни е ограничен чрез роли.

## Участници и заинтересовани страни
- **Гост:** разглежда началната страница, спортове, спортни центрове и игрища, може да се регистрира/влезе.
- **User:** създава резервация за себе си, вижда свои резервации, може да отменя собствена активна резервация.
- **Manager:** управлява игрища, спортове, центрове, всички резервации и плащания.
- **Admin:** изпълнява всички функции, управлява бизнес клиентите и присвоява роли.

## Функционални изисквания
| Код | Изискване | Статус в кода |
|---|---|---|
| FR-01 | Регистрация и вход с имейл и парола | Реализирано с Identity |
| FR-02 | Изход и защита на страниците | Реализирано |
| FR-03 | CRUD за спортове, центрове, игрища | Реализирано за Manager/Admin |
| FR-04 | Създаване и преглед на резервации | Реализирано с проверки за права |
| FR-05 | Забрана за припокриване на активни резервации | Проверка на ниво приложение |
| FR-06 | Управление на плащания | Ръчен CRUD запис, без платежен доставчик |
| FR-07 | Бизнес потребители (`Users`) | CRUD само за Admin |
| FR-08 | Промяна на роля | Само за Admin |

## Нефункционални изисквания
- Достъпен уеб интерфейс с Razor Views и български етикети.
- Server-side `ModelState` validation и SQL constraints (PK, FK, UNIQUE, CHECK, NOT NULL).
- Паролите се хешират чрез ASP.NET Core Identity; cookie authentication с HttpOnly/Secure.
- CSRF защита на изменящите заявки и `[Authorize]` за ограничените маршрути.
- Обработване на типични грешки (невалиден час, повторен имейл, липсващ запис, FK конфликт).

## Извън обхвата
Онлайн разплащания, известия по имейл, възстановяване на парола, публично хостване, мобилно приложение и автоматично обновяване на Figma дизайн. Проектът е учебен, а не готов за продукция.

## Критерии за приемане
Създаване/редакция/изтриване на съответния запис, отказ при невалидни стойности, липса на достъп до забранени маршрути, неуспешна резервация за зает час, правилно създадени 6 бизнес таблици и Identity база.
